# Communications UFHOB — transition de production

La messagerie humaine est le domaine `communications` (`/messages/`). Les événements logiciels restent dans `notifier` et le centre `/notifications/`. Aucun contenu de conversation n'est inclus dans les notifications de nouveau message, les événements WebSocket ni les journaux applicatifs.

- Annuaire : `communications.services.get_visible_contacts` est la politique serveur ; étudiant = cohorte et enseignants affectés, enseignant = classes affectées, staff = école et campus, GLOBAL = périmètre institutionnel. Les demandes de création directe et de groupe revalident la politique côté serveur.
- Conversations : clé directe triée pour éviter les doublons, participant individuel pour lecture/archive/sourdine, historique limité à 50 messages à l'ouverture et 25 conversations par page. Le message est durable en base avant diffusion WebSocket ; la page garde un polling HTMX de 25 secondes.
- Fichiers : `CommunicationPrivateStorage` écrit sous `private_media/communications`, hors `MEDIA_ROOT`. Chaque téléchargement passe par une vue authentifiée qui vérifie la participation. Ne pas publier ce répertoire via serveur Web ou CDN. Une configuration B2/S3 privée reste une évolution de déploiement, pas une hypothèse codée en dur.
- Notifications : `NotificationTargetResolver` reconstitue la cible des nouveaux messages et des reçus de paiement depuis les identifiants métier, et le clic contrôle le destinataire et marque lu. Les anciennes URL internes sont conservées uniquement pour les événements historiques ; elles ne confèrent aucun droit supplémentaire sur la vue de destination.
- Compatibilité : les anciennes entrées dashboard et `/messagerie/` redirigent vers `/messages/`. Les migrations `0002` et `0003` copient fichiers et messages compatibles sans supprimer les données héritées. `0003` transforme chaque ancien couple auteur/destinataire en conversation directe, y compris les envois collectifs copiés par destinataire pour ne pas exposer les autres bénéficiaires.

Avant déploiement : exécuter les migrations sur **ufhob_db uniquement**, relever les lignes `notifier.NotificationMessage(event_type="internal_message", channel="in_app")` sans acteur ou destinataire et les fichiers anciens introuvables. Django refuse déjà les anciennes URL `/media/notifier/internal-messages/` et `/media/communications/`, y compris en DEBUG ; configurer **également** le reverse proxy/CDN pour refuser ces préfixes avant tout service statique de `/media/`. Les copies publiques préexistantes restent sur disque pour permettre la vérification des migrations : les déplacer en lieu privé après validation, sans supprimer les sources avant contrôle. Ces lignes restent intactes dans la source et nécessitent une revue manuelle ; ne pas supprimer l'ancienne table par commodité. Vérifier que `ENABLE_WEBSOCKETS`/Redis est opérationnel si le temps réel est attendu en production ; HTTP demeure fonctionnel sinon.
